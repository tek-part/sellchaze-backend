Store catalog editor — integration checkpoint, 2026-10-10

The merchant /store/products and administrator /stores/{id}/products screens
use the tenant-scoped catalog API. The existing B2B catalog remains separate.
Products support draft/public status, translated names/descriptions, pricing,
internal cost, category, SKU/barcode, weight, SEO fields, cover/gallery uploads,
and variants with translated names, attributes and independent prices.
Inventory edits use the existing expected-state checks and movement history.
Reserved orders prevent destructive product/variant changes.

Merchant resources return raw editorial values and translations; public
resources retain localized text and omit costs. Media removal validates product
ownership. New uploads are removed on rollback, old uploads after commit.
Images currently accept JPEG, PNG and WebP up to 2 MiB each, 12 per request.

StoreCatalogEditorTest covers multilingual round trips, multipart uploads,
foreign category/media/product rejection, private cost visibility, inherited
and zero variant prices, inventory and reserved base-product conversion.

This is an integration checkpoint, not full EasyOrders parity. Outstanding:
rich text/video, generated option combinations, digital delivery, import/export,
per-product integrations/currency/theme/advanced settings, product AI creation,
variant-aware card quick-add, complete mobile/dark-mode acceptance, media
cleanup on whole-product deletion, base-stock conversion policy, and complete
category selection for stores with more than 100 categories.

The rebuild is being integrated into main at the user's merge request.
Both deploy workflows now require explicit workflow_dispatch. Quality checks
and production environment protections remain intact. No production migration
or deployment is part of this merge. Editable frontend source parity with the
captured production release and live provider/MySQL concurrency acceptance
remain pending. The full competitor rebuild goal remains active.
