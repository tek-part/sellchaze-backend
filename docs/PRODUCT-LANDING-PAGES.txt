Product landing-page API

GET/PUT /api/v1/my-store/catalog/products/{product}/landing-page and the matching
admin store scope require products-edit. GET returns the schema-1 document, version,
and minimal editor product data. PUT accepts {version, document}; it locks the
tenant-owned product, validates a bounded document and its media ownership, sanitizes
static HTML and invalidates storefront caches after commit. Stale different edits
return409. Exact canonical retries are idempotent.

POST .../landing-page/media accepts one JPG/PNG/GIF/WebP image, at most10MB. It reuses
the product-media transaction and cleanup rules and never modifies the saved layout.
Document saves and media uploads never change product prices, options or stock.

The additive nullable landing_page migration does not rewrite old products and
refuses populated rollback. Standard mode retains content but returns no public
landing document. Public product detail resolves media IDs to URLs; cart catalog
does not carry the layout payload. Native catalog import/export preserves documents;
duplicates remap product-owned image identities. Managed files referenced in saved
landing documents are retained on product-media cleanup.

Static HTML/CSS must be rendered in an isolated opaque frame. The sanitizer is not
intended as permission to insert arbitrary merchant styles in the main application.
The paired frontend keeps actual checkout outside the untrusted static frame.

An active landing checkout joins the existing product one-page-checkout advertising
eligibility. This affects configured advertising values only on the product surface;
actual invoice, tax, shipping, inventory and payment amounts remain authoritative.

Exact competitor template presets, competitor-format conversion and activated AI
authoring remain separate unfinished scope. No production deployment is asserted.

Eleven custom testimonial designs can be selected or changed without replacing
merchant items. They include carousels, centered quotes, colored cards, a grid,
two animated rows and speech bubbles. The gallery uses neutral preview-only data;
empty published sections do not invent reviews, ratings or verified buyers.
Author, optional date/caption/platform, accent and card colors persist with the
layout. Motion pauses on hover/focus, has a pause control and honors reduced motion.
Section background images use the same owned-media validation, portability and
copy remapping as foreground images. FAQ question backgrounds are configurable.
Cleared optional text fields remain empty after JSON middleware normalization.
The storefront also accepts PHP's empty settings-map JSON representation ([]).

Nine promotional image layouts are available through a native diagram gallery.
Selecting a new layout preserves all merchant images and destinations, pads empty
editor slots when needed, and keeps extra images in additional groups. Public
rendering never substitutes demo photos. Image panels use cover fitting,28px
corners,20px gaps, responsive columns and a reduced-motion-aware load animation.
Clicking an image in the editor opens its item properties without following links.

Banner images may target an own-store product, category or published page. The
products-edit destination endpoint returns only bounded public-safe labels/URLs,
with literal search, pagination and selected-item recovery. Stored references
follow current public paths and become unlinked if unavailable; drafts/foreign
entities are not exposed. Published page labels use publication snapshots.
Native page/catalog exports replace references with portable URLs. Exported files carry URLs instead of numeric destination identities; ordinary
duplication retains existing links
and remaps image ownership. Unavailable destinations must be fixed before native
page export. The existing landing migration is required; this phase adds no tables.

Store-feature landing presets features-1 through features-45 use the existing
store_features family and versioned document. Validate family boundaries, section
and item color values, motion and owned image references. Canonicalize motion to
a JSON boolean; clear optional editor text as usual. Public/native export removes
owned numeric image identities; product copies remap them. Reordering and design
changes retain merchant text, images, icons and links. The frontend implements
cards, benefits, pills, split grid, logos, merchant-entered numbers, a statement
and tickers without commercial sample promises or inferred counts. Native import
is not competitor-format conversion. No new migration or production deployment.

FAQ variants faq-1 through faq-35 belong exclusively to faq sections. Existing
versioned saves, public serialization, owned-media validation and native catalog
transfer preserve every question, plain/rich answer, image, URL, color and motion
setting. Extra questions are never truncated to a preset's initial slot count.
Invalid variants, crossed families, foreign media and malformed colors cannot
overwrite the saved document. Empty slots contain no generated commercial policy.
The native frontend supplies accessible single-open accordions and35 differentiated
layouts; no new database migration or commerce mutation is introduced.
Landing-page text, HTML/CSS and image alt fields bypass automatic trimming only
within the landing document endpoint. Other API fields retain ordinary trimming.
Versioned save/edit/restore tests retain leading/trailing whitespace and newlines.
