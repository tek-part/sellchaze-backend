Store checkout phone blocking (2026-10-10)

Merchants and employees with store.orders.manage can list/search blocked numbers,
add a valid local/international phone, edit an internal note, unblock/reactivate
and inspect paginated actor history. Every operation is scoped to the current
store, also available through the explicitly authorized stores/{store} routes.
Responses are private/no-store. Public storefront routes never expose the list.

Canonical E.164 identity uses the order-limits country setting and libphonenumber.
Equivalent national/international/Arabic digit formats share one record. Repeating
an active add cannot overwrite its note; an inactive number requires explicit
reactivation. Updates carry a version; conflicting decisions return409. Identical
retries do not create extra history. Unblock retains history rather than deleting.

Any active block makes a valid phone required at checkout, including email-only
digital carts. Authoritative checkout checks the canonical number before creating
an order, even when the daily order quota is disabled. Block mutations and checkout
lock the Store row in the same order. Rejected checkout rolls back cart/inventory/
coupon/code/order changes. Previously created orders, idempotent checkout replay,
private receipts and payment retry continue to work after a later phone block.
SQLite tests do not establish real concurrent MySQL behavior or throughput.
