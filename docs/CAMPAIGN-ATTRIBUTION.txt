Merchants can create a tagged campaign URL in the frontend and see the source and
campaign name on the resulting order. The visitor supplies these two labels; they
are attribution hints, not independent proof of an advertisement or payment.

POST storefront/checkout accepts an optional marketing_attribution object with
only source and campaign, bounded100/200 characters, no control characters or
markup. It requires a valid optional analytics session UUID when supplied. The
two labels are trimmed/whitespace-normalized into an immutable first-placement
snapshot. Existing checkout idempotency/recovery/payment retries preserve it;
changing a completed request body conflicts rather than creating another order.
No URL, referrer, click identifier, contact or provider credential is retained in
this object, and no advertising/provider call is introduced. Attribution can
survive a delayed/failed metrics visit; no fabricated visit or analytics session
is inserted into the existing first-party counters to make it appear successful.

store_orders. Existing order values stayNULL. A populated snapshot prevents down()
until history has been preserved. Raw StoreOrder serialization and the public
checkout/receipt/account resources omit it. MerchantOrderResource explicitly
returns it under existing owner/tenant/order permissions. No unrelated store,
stock, shipping, tax, offers, customers or historical order settings are changed.
